This draft describes data handling found in the NOW — Daily Planner app and server code reviewed for this version. It does not describe device-platform or provider practices that have not been verified.

Information stored on your device

NOW stores information you enter in local app storage on your device. This can include activities (names, dates, start and end times, categories, notes, and completion status); study tasks; workout and sports sessions; meals and nutrition targets or plans; personal goals; profile details; and your language selection.

Profile details may include your display name, schedule and availability, study interests and goals, training preferences and limitations, food preferences, disliked ingredients, allergies, dietary restrictions, meal schedule, cooking preferences, and nutrition goals. Some of these details may reveal sensitive health-related information.

NOW provides email-and-password account sign-in through Clerk and does not save activities or profile records to a NOW application database. Local storage is implemented with AsyncStorage and is scoped to the signed-in Clerk user where supported; the code reviewed does not establish that this storage is encrypted or how operating-system backups may handle it.

AI planning and coaching

When you request AI features, the app sends a request to the NOW server, which sends feature-specific content to OpenAI. The OpenAI API key is used by the server, not embedded in the mobile app. Avoid entering information in a prompt that you do not want sent for AI processing.

  • Plan my day: OpenAI receives your free-text request, local date and time, time zone, and up to 300 existing activity blocks containing names, dates, and start/end times. When you regenerate a plan, the current draft and names of activities you removed may also be sent. The app sends an optional profile subset to the NOW server, but the current day-planning route does not include that profile in its OpenAI request.
  • Workout Coach: OpenAI receives selected training profile fields (goal, experience, preferred days, availability, equipment, exercise preferences, and limitations), plus activity names, dates, and times for the next seven days, local date, and time zone.
  • Nutrition Coach: OpenAI receives non-empty food preferences, disliked ingredients, allergies, dietary restrictions, meal schedule, cooking preferences, and nutrition goals, plus local date and time zone. This request does not include the activity schedule.

AI results are returned to the app. In the reviewed flows, you can review the result before confirming it for local saving. OpenAI’s retention, use, and processing terms depend on the applicable provider account and settings; those details have not been verified for this draft.

Subscriptions and RevenueCat

NOW uses Clerk for email-and-password sign-up and sign-in. New sign-ups are verified with a code sent by email, and password reset also uses an email code. Clerk processes authentication and session information under its own terms and privacy notice. NOW uses the verified Clerk user ID to scope planner data on the device and as the RevenueCat App User ID. The app reads the active premium entitlement from RevenueCat; Premium AI requests are separately checked by the NOW server against RevenueCat using the verified Clerk identity. The reviewed app code does not send your activities or profile to RevenueCat. RevenueCat and the relevant Apple App Store or Google Play store process subscription and transaction information under their own terms. The exact provider-side data handling has not been independently verified here.

Service operation and rate limits

To apply AI request limits, the NOW server stores rate-limit records in its database. They include SHA-256 hashes derived from the verified Clerk user ID and request IP address, plus a request count and time-window/expiry fields. Account deletion removes the user-specific rate-limit record; it does not remove IP-based network rate-limit records. When a later rate-limit request runs the cleanup query, expired rows are deleted only after their expiry is more than seven days past; the timing depends on later requests and is not a fixed deletion guarantee. These hashed identifiers may still be linkable and should not be treated as guaranteed anonymous data.

The reviewed application logger records request ID, method, path, and response status rather than request bodies or IP addresses. Hosting-provider infrastructure logging was not reviewed.

Analytics, accounts, and advertising

No app-level analytics or advertising-tracking implementation was found in the reviewed app and server source. NOW does provide account sign-in through Clerk as described above. This statement is limited to the code reviewed; it does not describe data collection by device operating systems, app stores, or third-party providers.

Deletion and retention

In Settings, a signed-in user can choose “Delete my NOW account,” review a warning, and confirm. The NOW API uses the verified Clerk session to remove that account’s user-specific AI rate-limit record and then requests deletion of the same Clerk account. The app clears that account’s activities, study, workout, sports, meals, nutrition plans and targets, goals, and profile from this device only after the server confirms account deletion. If older unscoped data was explicitly assigned to that account during migration, its recovery copy is removed too; unassigned or differently assigned legacy data is preserved. If account deletion cannot be confirmed, local planner data is left in place and the app reports that the result is uncertain. If Clerk deletion succeeds but local storage cleanup or sign-out fails, the app reports that local cleanup could not be confirmed. This action does not cancel an App Store or Google Play subscription, remove data from other devices, delete information already sent to OpenAI, erase RevenueCat or store transaction records, or remove IP-based network rate-limit records. Other rate-limit records follow the cleanup behavior described above. Provider retention and device-backup retention have not been verified, so this draft makes no guarantee about them. If you cannot sign in to use the in-app flow, see the account-deletion request instructions.

For support or privacy questions, contact perisfortaletp@gmail.com.

Este borrador describe el tratamiento de datos que aparece en el código de la aplicación y el servidor de NOW — Daily Planner revisado para esta versión. No describe prácticas de plataformas o proveedores que no se hayan verificado.

Información guardada en tu dispositivo

NOW guarda la información que introduces en el almacenamiento local de la aplicación en tu dispositivo. Puede incluir actividades (nombres, fechas, horas de inicio y fin, categorías, notas y estado de finalización); tareas de estudio; sesiones de entrenamiento y deportes; comidas y objetivos o planes nutricionales; metas personales; datos del perfil; y el idioma seleccionado.

Los datos del perfil pueden incluir tu nombre visible, horario y disponibilidad, intereses y metas de estudio, preferencias y limitaciones de entrenamiento, preferencias de comida, ingredientes que no te gustan, alergias, restricciones alimentarias, horarios de comidas, preferencias de cocina y objetivos nutricionales. Algunos de estos datos pueden revelar información sensible relacionada con la salud.

NOW ofrece inicio de sesión con correo electrónico y contraseña mediante Clerk y no guarda actividades ni perfiles en una base de datos de NOW. El almacenamiento local usa AsyncStorage y, cuando corresponde, se organiza según la cuenta Clerk que inició sesión; el código revisado no demuestra que esté cifrado ni indica cómo pueden tratarlo las copias de seguridad del sistema operativo.

Planificación y asesoramiento con IA

Cuando solicitas funciones de IA, la aplicación envía una solicitud al servidor de NOW, que envía a OpenAI el contenido correspondiente a cada función. La clave de OpenAI se usa en el servidor y no está incluida en la aplicación móvil. Evita introducir en un prompt información que no quieras enviar para su procesamiento mediante IA.

  • Planifica mi día: OpenAI recibe tu solicitud en texto libre, fecha y hora locales, zona horaria y hasta 300 actividades existentes con nombre, fecha y horas de inicio y fin. Al regenerar un plan, también pueden enviarse el borrador actual y los nombres de las actividades que quitaste. La aplicación envía al servidor de NOW un subconjunto opcional del perfil, pero la ruta actual de planificación diaria no lo incluye en la solicitud a OpenAI.
  • Entrenador de entrenamiento: OpenAI recibe algunos campos del perfil de entrenamiento (objetivo, experiencia, días preferidos, disponibilidad, equipo, preferencias de ejercicios y limitaciones), además de nombres, fechas y horarios de actividades de los próximos siete días, fecha local y zona horaria.
  • Entrenador de nutrición: OpenAI recibe los campos no vacíos de preferencias de comida, ingredientes que no te gustan, alergias, restricciones alimentarias, horario de comidas, preferencias de cocina y objetivos nutricionales, además de fecha local y zona horaria. Esta solicitud no incluye el horario de actividades.

Los resultados de IA se devuelven a la aplicación. En los flujos revisados puedes revisar el resultado antes de confirmarlo para guardarlo localmente. La conservación, el uso y el tratamiento de datos por OpenAI dependen de la cuenta y la configuración aplicables del proveedor; esos detalles no se han verificado para este borrador.

Suscripciones y RevenueCat

NOW usa Clerk para registrarse e iniciar sesión con correo electrónico y contraseña. Los registros nuevos se verifican con un código enviado por correo, y el restablecimiento de contraseña también usa un código por correo. Clerk procesa la información de autenticación y sesión según sus propias condiciones y aviso de privacidad. NOW usa el ID de usuario de Clerk verificado para asociar los datos del planificador en el dispositivo y como App User ID de RevenueCat. La aplicación lee en RevenueCat el entitlement activo premium; las solicitudes Premium de IA también se comprueban por separado en el servidor de NOW con RevenueCat y la identidad Clerk verificada. El código revisado no envía a RevenueCat tus actividades ni tu perfil. RevenueCat y la tienda correspondiente de Apple o Google procesan información de suscripciones y transacciones según sus propias condiciones. El tratamiento exacto de datos por esos proveedores no se ha verificado de forma independiente en este borrador.

Funcionamiento del servicio y límites de uso

Para aplicar límites a las solicitudes de IA, el servidor de NOW guarda registros en su base de datos. Incluyen hashes SHA-256 derivados del ID de usuario Clerk verificado y de la IP de la solicitud, además de un contador y campos de ventana de tiempo y caducidad. La eliminación de la cuenta borra el registro de límites de ese usuario, pero no los registros de límites de red basados en la IP. Cuando una solicitud posterior ejecuta la consulta de limpieza, solo se eliminan las filas cuya caducidad lleva más de siete días vencida; el momento depende de solicitudes posteriores y no es una garantía de eliminación en un plazo fijo. Estos identificadores con hash aún podrían permitir relacionar registros y no deben considerarse anónimos de forma garantizada.

El registrador de la aplicación revisada guarda el identificador de solicitud, método, ruta y estado de respuesta, no el cuerpo de la solicitud ni la IP. No se revisaron los registros de infraestructura del proveedor de alojamiento.

Analítica, cuentas y publicidad

No se encontró una implementación de analítica de la aplicación ni de seguimiento publicitario en el código revisado de la aplicación y el servidor. NOW sí permite iniciar sesión mediante Clerk, como se describe arriba. Esta afirmación se limita al código revisado; no describe la recopilación de datos de los sistemas operativos, las tiendas de aplicaciones o proveedores externos.

Eliminación y conservación

En Ajustes, el usuario que inició sesión puede elegir «Eliminar mi cuenta de NOW», revisar el aviso y confirmar. La API de NOW usa la sesión Clerk verificada para eliminar el registro individual de límites de IA de esa cuenta y después solicita borrar la misma cuenta Clerk. La aplicación borra de este dispositivo las actividades, los datos de estudio, entrenamiento, deportes, comidas, planes y objetivos nutricionales, metas y perfil de esa cuenta solo después de que el servidor confirme la eliminación. Si datos antiguos sin asociar se asignaron explícitamente a esa cuenta durante la migración, también se elimina su copia de recuperación; los datos antiguos sin asignar o asignados a otra cuenta se conservan. Si no se puede confirmar la eliminación de la cuenta, los datos locales del planificador se conservan y la aplicación informa que el resultado es incierto. Si Clerk elimina la cuenta pero falla la limpieza local o el cierre de sesión, la aplicación informa que no pudo confirmar la limpieza local. Esta acción no cancela una suscripción de App Store o Google Play, no elimina datos de otros dispositivos, no borra información ya enviada a OpenAI, no elimina registros de transacciones de RevenueCat o de la tienda y no elimina registros de límites de red basados en IP. Los demás registros de límites siguen el proceso de limpieza descrito arriba. No se verificó la conservación de datos por proveedores ni por copias de seguridad del dispositivo, así que este borrador no ofrece garantías al respecto. Si no puedes iniciar sesión para usar esta opción, consulta las instrucciones para solicitar la eliminación de la cuenta.
